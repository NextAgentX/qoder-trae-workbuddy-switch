# v2026.11.171651

## 客户端「关不掉」不再卡住切换

- Windows 上有一类**已被系统驱动扣住的内核残留**：进程列表里仍能查到，但已没有任何可执行线程，既不会写盘、也无法被结束任务清掉。此前按进程名判断「客户端还在运行」，会把这类残留当成活着的客户端，导致切换时反复提示关不掉。
- 现在改按**线程数**判断：只有明确观测到线程数为 0 才算已退出；查询失败时仍按「在运行」处理，避免误判后去改客户端正在写的数据。
- 该判据统一覆盖 WorkBuddy / CodeBuddy、Trae、VS Code、JetBrains 与 CodeBuddy CN 的检测与关闭路径。
- 关闭超时的提示同步改写：不再让用户去手动结束那些本来就结束不掉的残留进程，改为说明原因并建议稍后重试。

## 缓存命中统计口径

- 未观测到缓存的请求不再进入命中率分母，「缓存命中率 0%」现在确实意味着「测到了未命中」，而不是「没测过」。
- 统计页与网关侧的缓存口径对齐，Windows 端开关缓存时的命中率不再显示为 0%。

## 网关会话与用量统计

- Trae 网关的会话用量统计补齐了缓存池三态（明确有池 / 明确无池 / 未回报），未挂缓存池时的「缓存 0」不再被误记成命中。
- Responses 用量统计区分「未上报缓存」与「明确上报 0」两种情况，避免前者污染命中率。
