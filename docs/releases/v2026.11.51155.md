## 🚀 新功能

- 用量页的**网关账本**现在记录缓存命中量，趋势视图多一张「缓存命中」卡（命中量 + 命中率），模型表多一列「命中率」—— 直接回答「哪个模型没命中」。按账号 / 按密钥的命中量也在账本里，接口层已带出。
- **Trae / Qoder 网关开始记录缓存命中**：此前只有 WorkBuddy 侧写这个字段，另外两条产品线连分钟级的命中率都看不到。四种上游写法都认（DeepSeek `prompt_cache_hit_tokens` / OpenAI `prompt_tokens_details` / Anthropic `cache_read_input_tokens` / 裸 `cached_tokens`）。

## 🛠 其他

- **修掉「命中率恒为 50%」的根因**：`/v1/messages` 出口的 `input_tokens` 原先直接抄上游 `prompt_tokens`（**已含**命中量），又单列了 `cache_read_input_tokens` —— 客户端按 Anthropic 语义把两者相加，命中量就被算了**两遍**：输入总量翻倍、命中率腰斩。现在 `input_tokens` 会先减掉命中量，三个出口（非流式、`message_start`、`message_delta`）统一走同一个换算点。
- **Trae 出口补上 `cached_tokens`**：`prompt_tokens_details.cached_tokens` 在真有命中时才会出现（没命中量时整个键不写）。此前 Trae 线的客户端看到的输入含命中、却没有任何命中量可读，表现成「缓存从不命中」，与 WorkBuddy 线口径不一致。
- 命中率的口径统一成三条：分母只取**输入侧**（含输出会把 90% 算成 9%）；命中量绝不进 `total`（它是 `input` 的子集）；**「未观测」显示「—」而不是 0%** —— 两者混同会让人去查一个并不存在的缓存问题。
- 账本新增的是 `cached` 一列，**不回溯填历史**：网关日志是环形窗口，回填只能拿到几分钟样本，那份数字比「没有」更容易被读成「历史命中率就是这么低」。升级后头几天看到「—」是诚实的，第二天起自动齐全。
- 新增门禁 `check:cache-hit`（8 条）：用生产代码现场转译跑真断言，钉住上面三条口径。它在开发中当场抓到一处真 bug —— 「没观测到」仍返回 0，界面会渲染成「0% 命中」。
- 版本号统一为 2026.11.51155（全部载体校验通过）。

## 已知限制

- **客户端账本的命中率仍是旧口径**：本次只把网关账本补齐（预研方案的 P0/P2）。客户端侧（扫 `projects/*.jsonl`）的命中率来自 `token_stats`，那是另一条统计路，两边的分母口径不同，**不要跨账本比较**。
- 升级当天的历史命中量不可得：账本里那一列要等本次之后的请求才陆续有值。
- 上游压根不报缓存字段的模型，命中率会一直是「—」。这是「没数据」，不是「没命中」。
- macOS 安装包仍未签名与公证：从网络下载后如提示「已损坏」，执行 `xattr -dr com.apple.quarantine /Applications/BuddySwitch.app`。
- 「自动刷新」仍默认关闭：需要时在「设置 · 通用 · 积分自动刷新」开启；各页面都保留了手动刷新入口。
