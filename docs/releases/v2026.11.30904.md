## 🐛 问题修复

- 长会话不再被误报「有分歧」：此前逐行指纹只存前 512 行，判据却拿它当全文比，**任何超过 512 行的会话组都被无条件判成「有分歧」**——逐字节相同的副本也报分歧，而「安全同步（只追加）」按钮再也不出现，用户只能走**覆盖式**统一（会丢目标侧的新行）。现在按整份摘要与前缀验证判定，一致的回到「已一致」，真落后的能正常走只追加同步。
- 「共同旧版 N 条」不再拿比对窗口的上限冒充真值：超出比对窗口且确有分叉时，界面改口说「至少 N 条」。
- Trae 切换账号不再被要求「先保存登录态」：合并客户端之前的旧快照若还躺在历史目录里，切换前会**自动补搬一次**再判定（幂等、只增不改）；仍然找不到时，报错会直接指出该账号的快照**实际在哪个目录**（含另一个区域），而不是让用户再存一遍。
- Codex / T3 Code 的 MCP 工具不再整组消失：`/v1/responses` 入口此前把 `type: "namespace"` 的工具直接丢弃——请求 200、回答正常、**没有任何报错**，只是模型永远调不到 MCP 工具。现在会摊平后发给上游，并在工具调用事件里还原命名空间与原始工具名，多轮对话的调用记录也能对上。
- Qoder 国际版「无法解密现有登录态」现在能自证原因：报错会带出**密文形态**（v10 / v11 / 未知前缀+长度），并区分「客户端换了存储格式」与「钥匙串里的同名条目已陈旧」两种处置，不再是一句没有下文的「无法解密」。

## 🛠 其他

- Trae / Qoder 的 `deepseek-v4.1-flash` 现在会声明图片输入能力：这两条产品线的模型清单没有能力字段，客户端因此隐藏了上传入口。模型页会把「网关内置表声明」与「上游目录声明」**分开显示**，仍可手动覆盖。
- 版本号统一为 2026.11.30904（全部载体校验通过）。

## 已知限制

- macOS 安装包仍未签名与公证：从网络下载后如提示「已损坏」，执行 `xattr -dr com.apple.quarantine /Applications/BuddySwitch.app`。
- Anthropic 入口（`/v1/messages`）默认仍不转发图片，需要 `BUDDY_SWITCH_ANTHROPIC_FORWARD_IMAGES=1` 才透传；OpenAI 兼容入口（`/v1/chat/completions`）本来就透传。
- 长会话在比对窗口（512 行）之外分叉时，「共同旧版」只能给出下界，界面会写「至少 N 条」。
