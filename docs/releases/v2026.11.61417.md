## 🐛 问题修复

- 修复健康账号被误标「需重新登录」：刷新请求遇到断网（code=-1）或 HTTP 5xx 错误页时，后端不再当成凭据被拒，只把可读原因挂在返回值上、不写进账号库；业务拒绝码（12153 invalid_grant / 401 / 403）仍照旧落标记（issue #171）。
- 修复徽章滞留：后台清除标记后开着的页面不必重开窗口——60 秒轮询在刷新状态之外同时重拉国内版与国际版的账号列表，≤60s 内徽章自动消失（issue #171）。
- 手动「刷新 Token」遇到暂时性失败改为警告提示（含原因），不再冒充「刷新成功」、也不再误报「需重新登录」。
- 保活结果新增 `transient` 一态：暂时性失败既不算 `ok` 也不算 `failed`，下一轮保活自然重试；已带历史误标的账号本轮暂时性失败也优先报 `transient`。

## 🛠 其他

- 暂时性失败原因 `refreshTransientError` 只挂在刷新返回值、不落账号库；桌面命令与 webui 两种下发形态都在 API 边界归一成同一个展示字段。
- 轮询重拉账号列表带 in-flight 去重，避免与页面加载 / 相邻 tick 并发时旧列表覆盖新列表；不设 loading，不闪骨架屏。
- 新增回归测试覆盖断网 / 5xx / 12153 / 401 / 403 与保活三态；门禁加钉「暂时性失败不误标 + 轮询补账号列表」。
- 版本号统一为 2026.11.61417（全部载体校验通过）。

## 已知限制

- 刷新只能换取新的 access token，无法延长上游签发的有效期；refresh token 链条一旦断开（加密信封解不开、上游会话被清理返回 12153、11140 硬禁用），本地定时保活救不回来，仍需重新登录或重新导入凭据。
- Trae 从本机抓取 / 备份导入的 JWT 没有 refresh token，也不带设备私钥，不支持自动续期，只能重新获取 JWT。
- macOS 安装包仍未签名与公证：从网络下载后如提示「已损坏」，执行 `xattr -dr com.apple.quarantine /Applications/BuddySwitch.app`。
- 「积分自动刷新」仍默认关闭：需要时在「设置 · 通用 · 积分自动刷新」开启；Token 保活默认开启，与积分刷新是两个开关。
