## Trae 的 `/v1/models` 现在会告诉你每个模型支持哪些思考档位（#127）

- 每个模型条目多了两个字段：`thinking`（`supported` / `unsupported` / `unknown`）与 `reasoning_effort: { options: ["light","high"], default: "high" }`。
- 数据只来自**客户端清单里该模型自己声明的档位**（就是你界面上「思考档位」那一列的来源）。没声明就整个键省略 —— 不会写一个空的 `[]` 让客户端误以为「支持 0 个档位」。
- `thinking: unknown` 表示「这一版清单没下发」，**不是**「不支持」。

## `reasoning_effort` 现在能被映射到 Trae 的档位（默认关，需要手动开）

- 此前顶层 `reasoning_effort` 原样透传给上游，而 Trae 不认这个字段（按未知字段忽略）⇒ 配了等于没配。
- 现在设 `BUDDY_SWITCH_TRAE_REASONING_EFFORT=1`（`on` / `true` / `yes` 同效）后，网关会按**该模型声明的档位**做一次映射，补上 `model_info.reasoning_effort_level`；顶层字段原样保留。
- 映射规则：声明词表里能精确命中就用清单的写法；否则按强度序取「不高于请求档的最高档」，全都更高则退到最低；声明为空或取值认不出一律**不改**。
- **为什么默认关**：上游收不收这个字段、收错了是静默忽略还是 `4001`，目前没有实测。默认打开一旦上游严格校验，就是把「配了不生效」换成「整条请求被拒」——那更糟。这与「Anthropic 入口默认不转发图片」是同一条纪律。
