## 🚀 新功能

- 网关的「请求日志」多一列**积分**（WorkBuddy / Qoder）：逐条显示上游这次回报的消耗，不用再去「积分」页反推「刚才那一发花了多少」。
- 表头自带口径提示：`0` 是**上游没上报**，不是免费；逐条相加是**请求口径**，与「积分」页的**余额口径**对不上是正常的（重试 / 多设备会重复计入）。
- Trae 侧**不显示**这一列：它的上游只回报 token、不回报积分，画一列恒 0 只会被读成「Trae 免费」。

## 🛠 其他

- 请求日志里的三种「没有」严格分开：`—`（升级前的老条目，没有这个字段）/ `0`（上游没上报）/ `<0.001`（极小但非零）。把极小值抹成 `0`，会让「花了钱」和「没报」长得一模一样。
- 修掉 Qoder 日志归一的错挂风险：原先按**未过滤**的原始数组下标附加 `region` / `credits`，数组里混进一条脏值就会让之后每条的积分整体挪到上一行 —— 显示成「这一发花的是别人那发的钱」。现在按与 Trae 归一化逐字相同的过滤重建对齐数组，长度对不上就整列退回 `—`（宁可显示不知道，也不猜）。
- 原型（`docs/prototype`）的请求日志表补上「版本」「积分」两列并按平台分化，夹具补齐三态样本 —— 设计稿与真实组件不再各说各话。
- 版本号统一为 2026.11.51421（全部载体校验通过）。

## 已知限制

- 升级前的日志条目没有 `credit` 字段 ⇒ 显示 `—`，**不回溯、也不按 0 计**：那批请求当时就没记这个数，编一个出来比留空更糟。
- 跨作用域降级产生的日志行（把 WorkBuddy 的请求转到别的产品线）写的是 `credit: 0.0`，会显示 `0` —— 那一发在本侧确实没有积分可报。
- Qoder 的积分来自上游 `usage.credits`，与 token 不是线性关系（可能含按次 / 模型倍率），别拿它当「token → 积分」的换算样例。
- macOS 安装包仍未签名与公证：从网络下载后如提示「已损坏」，执行 `xattr -dr com.apple.quarantine /Applications/BuddySwitch.app`。
- 「自动刷新」仍默认关闭：需要时在「设置 · 通用 · 积分自动刷新」开启；各页面都保留了手动刷新入口。
