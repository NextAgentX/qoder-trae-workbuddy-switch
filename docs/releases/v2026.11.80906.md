## Trae 请求日志能显示「这次花了多少积分」了（#185，社区贡献）

- Trae 的流式响应只回报 token，不带积分；上游账单又比请求晚 6–8 秒、且不能按会话对齐。现在由后台**事后回填**：从账单表按「输入/输出 token 相等 + 时间邻近 + 已消费行去重」匹配，写回请求日志的「积分」列。
- 日志的积分列有三态：数字（已回填）、`…`（还在等出账）、`—`（不会再有）。升级前写入的老日志不回填，显示 `—`。
- 三平台日志都加了刷新入口；Trae 的刷新会顺带催一次回填。
- 上游调用次数是收敛的：没有待回填条目就一次请求都不发；单账号冷却、分页上限、15 分钟/4 次放弃、429 退避。

## Trae 国际版不再把「未知额度」显示成 0（#186）

- 现象：国际版账号卡片显示「积分 0 · 长期有效」，即使账号明明还有免费配额。
- 原因：`credits_limit` 只描述**积分制**额度，Free / SOLO 账户的权益包里根本没有这个字段，旧实现把「读不到」当成「0 积分」写进了缓存。
- 现在这类账号显示「—」（未知），并把一次性的**结构特征**写进应用日志（只记键名、不含数值）。如果你在 Trae 国际版遇到这个，把日志里 `积分读数跳过：…` 那一行贴到 issue #186，就能决定要不要再补一个「套餐额度」维度。
