# 统一网关斜杠模型 ID 设计

> 状态：已确认
> 日期：2026-11-16

## 意图

统一网关对外公布的模型 ID 改用 `命名空间/模型ID`，例如 `wb-cn/minimax-m3.1-flash`，便于 CC Switch 按斜杠后的模型名识别模型品牌。此前保存的 `wb-cn:minimax-m3.1-flash` 请求仍须可用。

斜杠是统一网关自己的命名空间约定，不是 OpenAI 或 Anthropic API 定义的 provider/model 语法。两种 API 的请求都通过 `model` 字符串传模型 ID；统一网关在它自己的入口解析命名空间，再把裸模型 ID 转给上游。

## 目标与边界

- `GET /v1/models` 的模型 `id` 使用斜杠：`{namespace}/{upstream_model_id}`。
- 请求解析兼容 `/` 与 `:` 两种分隔符；命名空间只接受注册表中的精确 ID。
- 解析后仅剥离命名空间和一个分隔符，上游仍收到原始模型 ID；模型 ID 自身剩余的 `/` 或 `:` 不变。
- 不改变独立网关的模型 ID 与路由规则。
- 本次改变统一网关清单输出格式；现有客户端若硬编码冒号模型 ID，可继续调用。

## 方案

1. **只接受斜杠请求，清单仍返回冒号**：改动较小，但 CC Switch 拉取清单时仍看不到它需要识别的斜杠模型名。
2. **清单和请求统一改为斜杠，继续兼容冒号请求（采用）**：清单对新客户端直接给出斜杠 ID，旧配置继续有效；代价是清单 ID 格式发生变化。
3. **清单同时返回两套 ID**：客户端能选任一格式，但每个模型重复出现，容易造成重复选项与模型显示混乱。

## 实现约束

- 命名空间识别仍为 fail-closed 精确匹配，不做前缀猜测。
- `/` 和 `:` 仅在第一个分隔符处切分；未知前缀保持现有拒绝语义，不得静默路由到别的账号池。
- 同步更新统一网关架构与客户端接入文档、模型清单及路由行为约定。

## 验收条件

- 模型清单中的命名空间 ID 使用斜杠格式。
- `wb-cn/minimax-m3.1-flash` 与 `wb-cn:minimax-m3.1-flash` 都路由到 `wb-cn`，上游模型名均为 `minimax-m3.1-flash`。
- 已有命名空间精确匹配、授权、启用检查与未知前缀拒绝行为不变。
