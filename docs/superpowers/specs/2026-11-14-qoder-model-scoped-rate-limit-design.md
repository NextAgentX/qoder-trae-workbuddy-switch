# Qoder 账号可用性与模型级限流

## 意图

修复 Qoder CN 账号凭据有效、账号池有账号时，因账号级风险冷却被统一选号逻辑排除而返回“没有可用账号”的问题。

## 根因与目标

Qoder 池已将上游 `429` 记录为模型级 60 秒冷却；网关同时把它写入共享风险状态的账号级 `Cooling`。选号前 `account_blocked()` 会把该账号从所有模型中排除，旧版遗留的冷却记录也会继续生效。

Qoder 网关应只因持久化的账号级 `Paused` 状态而在全模型排除账号。模型级 `429` 由 Qoder 池管理；账号级请求速率与并发准入仍继续使用共享设置。WorkBuddy 和 Trae 的既有账号冷却语义不变。

## 方案

- A：保留账号级冷却，改善报错和恢复提示。诊断更清楚，但其他模型仍会被一并阻断。
- B：Qoder 网关选号忽略账号级 `Cooling`，只尊重 `Paused`；Qoder 上游 `429` 不再新增账号级冷却。选择 B，因为它与 Qoder 已有的模型级冷却设计一致，也兼容并绕过旧版遗留的账号级冷却记录。

## 范围与约束

- 仅调整 Qoder 网关转发的账号筛选与 `429` 风险状态写入。
- 认证拒绝产生的 `Paused` 仍阻止该账号；账号级速率、并发和最小间隔准入仍生效。
- 不改 WorkBuddy 的 `developer → system` 规范化；该转换已在三种入口共用的出站处理路径中实现。Issue 中代理日志与 request ID 的差异不足以证明网关代码绕过。
- 不处理 issue 中附带的请求正文日志开关和其他风控建议。

## 验收

四个账号即使存在旧版账号级 `Cooling`，Qoder 网关也不会因此对所有模型报“没有可用账号”；模型级冷却与认证暂停仍按各自既有语义生效。
