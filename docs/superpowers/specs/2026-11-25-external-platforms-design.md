# 豆包、Loomy、小浣熊独立平台设计

> 状态：已实施（2026-11-26；网关适配采用本软件直接代理；15 页面核对见 [对齐记录](../plans/2026-11-25-external-platforms-alignment.md)）

## 意图

豆包、Loomy、商汤小浣熊不再只是 WorkBuddy 积分页里的三类外部账号；它们各自成为产品切换器中的独立平台，并各有「概览 / 账号 / 用量 / 网关 / 设置」五个一级入口。用户切换平台后，页面、账号列表、余额和设置都只读写当前平台的数据。

## 目标与非目标

- 三个平台各自拥有独立、可刷新的 CN 平台入口和稳定 URL；它们加入前端平台切换器，但不进入 core 客户端/网关命令作用域。
- 五个入口全部有独立路由，并在侧栏中可见；三家不显示不适用的「会话」入口。
- 概览、账号、用量直接使用现有第三方账号凭据与余额读取能力，按平台过滤，不能把三家余额加在一起。
- 网关、设置拥有各自的页面和平台上下文；三家网关均由本软件独立监听并代理，端口、API Key、运行状态和模型目录互相隔离。
- 不把商汤小浣熊消费网页积分接口宣称成 SenseNova API；模型请求使用小浣熊消费客户端实际使用的上游协议。
- 保持 WorkBuddy、Trae、Qoder 已有页面、账户和网关行为不变；保留当前工作区里其他未提交改动。

## Approaches

1. **完整复制既有平台能力**：为三家分别实现账号授权、模型清单、网关上游、请求转发、用量流水和设置。最全面，但问题 #218 / #219 没有要求这些能力，且三家的授权和 API 协议不同。
2. **独立平台 + 本地直接代理（本设计采用）**：加入独立平台/作用域与五个路由；概览、账号、用量连接真实凭据与余额能力；网关独立监听并使用本平台账号凭据代理模型请求，模型、Key、端口与生命周期互相隔离。
3. **只加三个侧栏组，不进入平台作用域模型**：改动较少，但无法复用平台选择、作用域 URL、账号隔离和页面注册规则，因此不满足「各自独立」。

采用第二种方式是因为用户明确要求本软件直接代理。协议适配基于开源实现与本地 mock 上游验证；未支持的请求能力要明确返回兼容错误，不能静默丢弃字段。豆包媒体生成当前复用 Doubao2API 公开的 Samantha 消费端协议：图片 `/v1/images/generations`、视频 `/v1/video/generations`、音乐 `/v1/audio/generations`。图片 URL 输入限制为固定解析到公网地址的 HTTPS 图片；音频输入和原生工具调用仍无兼容路径。

## 产品与数据边界

- 产品标识：doubao、loomy、raccoon；每家先提供一个 cn 作用域，切换平台时进入其账号入口。
- 第三方积分账号存储按 provider 做强过滤；路由作用域与 provider 不匹配时拒绝读写。
- 概览展示该 provider 的账号数、可读取的余额汇总、最近刷新时间和错误状态。
- 账号页仅展示当前 provider 的账号，支持添加、删除和刷新。凭据仍只通过本地私有文件保存。
- 用量页展示上游余额、更新时间，以及本机成功采集的历史余额快照；快照变化不得标成上游消费流水。
- 网关页按 provider 展示监听地址、API Key、启动/停止状态、模型清单及 OpenAI 兼容接入示例；运行状态来自真实监听句柄。
- 设置页允许按 provider 设置余额自动刷新间隔与低余额提醒阈值；设置只影响对应平台。

## 五个入口的交互与视觉约定

三个外部平台的五个入口继续由同一组目的地导航承载，并复用 WorkBuddy / Trae / Qoder 已有页面原语；平台差异只体现在标题、数据、凭据和明确列出的协议限制上。

- 所有入口使用相同的页面宽度、页头字号/间距、作用域标签、卡片标题行、边框和留白节奏。
- 概览与用量使用 `StatTiles`；账号页使用统一账号卡片列表、加载骨架、空态与 shadcn 弹窗；用量页使用统一 `Tabs`；设置使用 `SettingsGroup` / `SettingsFieldRow`；网关页使用同一网关状态卡和模型徽标样式。
- 加载、错误、成功提示和空态遵循现有页面组件；添加/删除账号有明确操作反馈，删除必须经过确认。
- 用量仍清楚区分上游当前余额、本机采样差值和网关请求账本，不将它们合成服务方账单。
- 外部平台侧栏只显示五个实际入口；会话功能不适用时由能力门控隐藏，不渲染空页面。

### 原型逐入口对齐规格

视觉基准为 `docs/prototype/index.html` 加载的 `demo-app.js` / `demo.css`。对齐的是每页可见的信息层级、布局、控件排列、导航位置、尺寸节奏、空载/错误/加载状态和响应式行为；不能只复用颜色和卡片圆角。三个平台必须共享同一套页面骨架，确保同一入口在 Doubao、Loomy、Raccoon 间切换时结构不漂移。页面逐一验收如下：

| 入口 | 原型结构必须保留 | 外部平台的数据适配 |
|:--|:--|:--|
| 概览 | `viewOverview` 的页头与刷新操作；待处理区置顶；四项统计；统计图与右侧信息卡组成的响应式分栏 | 显示当前 provider 的账号数、余额、更新时间、错误或低余额提醒；不伪造原型中没有的数据。没有可用趋势时显示有解释的空态，仍保留图表卡的位置和标题层级 |
| 账号 | `viewAccounts` 的页头、搜索/排序/分组/卡片或表格切换工具栏、全选及批量操作区、账号列表容器；窄屏按原型断点折行 | 搜索、选择、删除、刷新和批量能力只操作当前 provider；若某项批量动作没有真实后端能力则不展示死控件。保持账号卡片密度、操作位置和空/加载状态 |
| 用量 | `viewUsage` 的页头、视图切换、统一参数工具条、下方视图内容区；参数条在切换视图时保持同一位置和状态 | 日期范围和筛选只显示有数据支持的控件；余额、请求统计、本机快照明确区分来源。缺数据时用空态占据对应内容区，不把缺失数据显示为零 |
| 网关 | `viewGateway` 的页头、左右分栏、左侧网关类型/子导航、右侧主内容；概览页保留状态行和接入说明卡，窄屏按原型转为纵向 | 每个平台展示真实的监听状态、端口、密钥操作、模型清单和接入地址。隐藏不适用分区，不以占位页冒充已实现能力 |
| 设置 | `viewSettings` 的页头、左右分栏、左侧分组子导航、右侧分组卡片和作用域说明；窄屏按原型转为纵向 | 仅提供当前 provider 已实现的独立配置，刷新间隔和低余额阈值按 provider 保存；其余分组不展示虚假或无效设置 |

逐平台核对矩阵为 3 provider × 5 入口，共 15 个页面。除上述原型信息层级外，还需检查路由直达、当前平台标题/作用域、页面宽度、子导航选中态、加载/空/错误状态、窄屏布局和控件实际行为。任何省略的原型控件都必须因数据或操作确实不适用，并在对应页面设计/文案中表达清楚；不得仅因当前页面已有简化实现而省略。

实现优先组合已有共享原语（`SideSubnav`、账号工具栏/批量栏、`ViewParamBar`、`StatTiles`、`SettingsGroup`、`SettingsFieldRow`、shadcn 控件）并补齐缺失组合。原型 HTML/CSS 仅作为视觉基准，不直接嵌入生产页面，以保持主题、无障碍语义、路由和真实数据操作的一致性。

## 实施边界与迁移

- 前端平台注册、独立 CN 路由、导航路由、命令面板与作用域可见性需要同步更新；旧可见性偏好迁移时新增三家入口。
- 后端外部积分 API 按 provider 隔离；客户端/网关 core Scope 保持原有六项，外部平台不能被误派到既有客户端路径或网关上游。
- 现有 external_credit_accounts.json 保持兼容；新增平台字段或读取过滤不能丢失已有账号。旧的 WorkBuddy 用量页第三方积分卡片继续可用，直到独立页面接管并完成无损迁移。
- 所有字符串进入中英文词表。文档地图与作用域注册检查同步更新。

## 验收标准

- doubao-cn、loomy-cn、raccoon-cn 均可从产品切换器选中，并有唯一、可直接打开的五个入口 URL。
- 每个入口都渲染本 provider 对应页面，不回落到 WorkBuddy、Trae 或 Qoder 页面。
- 添加账号、刷新、删除操作只影响当前 provider；列表不会泄露任何 provider 的凭据。
- 用量按 provider 显示，失败状态不会伪装成余额 0，也不会把不同产品积分合并；本机快照与上游流水明确区分。
- 自动刷新间隔和低余额阈值独立保存；阈值提醒只影响对应平台。
- 每个平台监听器只读取自身 provider 的凭据；每个接入 API Key 只接受当前平台请求；健康检查、鉴权、模型清单、普通与流式聊天均有 mock 上游验证。
- 三个平台的五个入口均通过逐入口对齐矩阵；15 个页面的布局与信息层级符合原型，且导航、窄屏布局、空/加载/错误状态和可见操作均已核对。
- 五个入口沿用同一页面壳、统计/卡片/设置/空态原语；账号增删和网关操作均有加载与结果反馈；三家平台不出现会话入口。
- 原有三平台注册表与账户路由继续工作，备份仍只覆盖其支持的六个 core 作用域。

## 依据

- GitHub issues #218 与 #219。
- 现有平台边界：src/lib/platforms/registry.ts、src/lib/scope.ts、crates/buddy-switch-core/src/modules/product.rs。
- 现有外部积分数据源：crates/buddy-switch-core/src/modules/external_credits.rs。
- 开源网关对比：[Doubao2API](https://github.com/2951461586/Doubao2API)、[loomy2api](https://github.com/Patrick130306/loomy2api)、[Buddy2api](https://github.com/wicm84266964/Buddy2api)、[Agent2API](https://github.com/7Crimson7/Agent2API)。它们证明消费级凭据可用于非官方代理，但不能直接复用为当前应用网关适配器；Agent2API 也提示私有协议可能变更并有服务条款风险。
- Gateway 协议能力因 provider 而异；豆包消费者凭据与 Ark API key 是不同授权面，小浣熊积分查询也不等于 SenseNova 模型 API。
