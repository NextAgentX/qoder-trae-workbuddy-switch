# 账号与出口处理

本项目保留各平台原有认证、设备身份和会话处理方式。账号切换不会写入 UID 派生的设备身份；WorkBuddy / Trae / Qoder 的账号请求使用各自网关的共享出站客户端。此设计不声称能消除平台侧账号关联，也不提供通过账号轮换或代理切换规避平台限制的保证。

## 账号凭据

WorkBuddy 切换时向官方客户端写入当前账号的认证快照；账号库仍保存在本地账号数据文件中。认证快照的单账号边界用于减少本地凭据暴露，不改变上游身份或设备标识。

## 出站网络

- 同一平台网关的账号使用共享 HTTP 客户端与共同出口。
- WorkBuddy 默认直连；`upstream_via_proxy` 允许在网络确实要求时让共享客户端使用系统代理。该选项不是账号级路由。
- 历史 `~/.buddy-switch/account_egress.json` 可能仍留在本机，但程序不再读取它；不会自动删除用户文件。
- 新增的账号独立代理配置与 `/api/gateway/account-egress` 管理入口已退役。

## 请求节奏与账号暂停

WorkBuddy、Trae、Qoder 分别按平台和 `cn` / `global` 区域保存可编辑的风控参数。设置项包括每账号每分钟请求数、账号/平台并发、账号最小请求间隔、暂时性故障尝试预算与限流回退冷却时间。各字段范围和默认值见三平台 API 服务页。

网关选号前会过滤已有持久暂停/冷却的账号；该账号当前请求仍不会因上游终态错误而换号。后台一个流程若需连续调用同账号，会等待配置的最小间隔；速率、并发、暂停或冷却拒绝仍 fail-closed。额外暂时性重试预算目前只用于 Qoder 模型目录的候选主机回退，并且只在连接前错误、408/425 或 5xx 时生效。

网关 LLM 请求在账号出站前执行准入；WorkBuddy、Trae、Qoder 的认证拒绝与账号级限流结果写入各平台的 `risk_control.json`。暂停与冷却会跨进程重启保留。受保护错误不触发换号重放。只有用户在官方渠道处理后，才应使用人工恢复入口清除对应平台/区域/账号的风险状态：

- WorkBuddy 账号池恢复操作同时清除该 uid 的 CN/Global 风险状态。
- 通用恢复命令：`recover_gateway_risk_account(platform, region, uid)`。
- 本地管理 API：`POST /api/gateway/risk/recover`，JSON 字段为 `platform`、`region`、`uid`。

POST 发生超时或连接中断时，上游是否已处理通常无法确定；这类请求不会自动重放。客户端主动发起的新请求仍会经过网关准入和平台自身限制。

## 适用边界

持久化请求准入覆盖三平台 LLM 网关 relay；同时接入 WorkBuddy token 刷新、签到、旅行、积分查询与模型目录请求，Trae 的 JWT 刷新、积分请求与模型目录请求，以及 Qoder 的 token 刷新、签到、额度、套餐、模型目录、活动/领奖和网页额度请求。Qoder 网页 Cookie 的 401/403 仅按网页会话失效处理，不会暂停同一账号的 API token；网页请求的 429 会进入账号冷却。OAuth 登录授权属于用户发起的凭据签发流程，不适用已登录账号的后台准入策略；新接入的自动化请求仍须按接口特性逐项验收。风控设置不承诺账号状态或平台处置结果。
