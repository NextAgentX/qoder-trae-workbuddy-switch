### 0.1 指纹口径（本报告的元规则）

**行数不作指纹，仅作参考规模；指纹 = sha256 + 取数时间。**

这不是形式主义。本次交付期间文件变了 **10 版**，其中 **`2814` 这一行数在 4 分钟内出现过四个不同 md5**：

| 时刻 | 行数 | md5 |
|---|---|---|
| — | 2792 | （成员 A 量） |
| — | 2796 | （成员 B 量） |
| — | **2811** | `d301507f` |
| — | 2799 | `83e67ede` |
| — | 2800 | `b9a8fcd3` |
| — | 2809 | `66ff6e1b` |
| — | **2811** | `9cbf3d48` |
| 18:27:20 | **2814** | `2f83be2b` |
| 18:28:42 | **2814** | `461b5ac2` |
| 18:30:19 | **2814** | `d3c3c8bf` |
| **终态 18:31:11** | **2814** | **`20c2b39e`**（sha256） |

两名成员在 2811 行上得出过不同结论、在 2814 行上得出过三次不同结论，**每一次都没人"错"——错的是拿旧指纹断言新状态**。`2814` 连续四版内容不同，说明**行数连「有没有变」都测不出来**；md5 还会回到旧值（`461b5ac2` 出现过两次），只有 **sha256 + 取数时间**这一对才唯一。

> **「已决定 ≠ 已落地」的对称命题是「已落地 ≠ 你上次量到的样子」。**
> 任何「已修复 / 未修复」的结论必须附取数时间。协作方的状态描述（数字、行号、"已改/未改"）只是**线索**，不是**证据**——写进文档前自己取一次。

> **补充：定版前最后半小时又有 3 处改动**（图表轴改为相对窗口、`.btn.weak` 补边框色、两个空括号填 `（1）`），全部包含在 18:31:11 终态内，详见 §3.4。**归属：1 处来自审查（图表时钟），2 处由构建师自查发现** —— 见 §3.4 的修正说明。

### 0.2 对比度判定口径

按 **gamma 编码 sRGB** 做 alpha 合成（CSS Compositing 规范行为，与 DevTools 一致）。
线性空间合成会系统性低估约 25%（`.badge.bad` 从 4.14 掉到 3.07），**不作为判据**。

**判定优先级：DevTools 取色器实测 > OKLab 手算 > sRGB 通道近似（不采信）。**
同一处三种手算可差 0.26（4.73 / 4.96 / 4.99），已接近门槛余量本身——**任何未注明合成空间与算法的对比度结论视为无效**。

### 0.3 审查方式

10 张截图逐张目视 → 针对性 grep 定位实现（未通读全文）→ OKLCH→sRGB 脚本实算对比度 → 跑自动断言交叉验证。**人工判断与脚本结论相互独立**，冲突时以本报告 §3 的证据为准（本次发生过：脚本 46 条全过，人工仍判出 1 条 P0 + 10 条 P1）。

## 3. 缺陷关闭状态

### 3.1 P0（阻断）

| 编号 | 问题 | 状态 | 证据 |
|---|---|---|---|
| **P0-1** | `.badge.bad` 文字压 16% destructive 软底，对比度 **4.14:1**，不达 AA 4.5（10.5px 小字）。3 处实例：客户端卡「被外部占用」、账号卡「已过期」、概览待处理「外部占用」，背景均为 `--card`，无一侥幸落在更深的 `--card-2` 上 | **已关闭** | 修后 `color:color-mix(in oklab, var(--destructive) 80%, var(--foreground))`，实测 **4.96–4.99:1**（两种 OKLab 算法），余量 0.49，混合色 `C=0.151` 仍为明确红色。连带复算 `.badge.ok` 4.71 / `.badge.warn` 5.21 未被碰掉 |

> **这是本次唯一的阻断项**，且由对比度"软底"场景补算发现——我们最初只算了纯色配对（全部通过），漏了「徽标文字压在自己色相的软底上」这个真实场景。

## 6. 交接说明（给真机实现者）

### 6.1 对比度判定：合成空间选错会导致「全部推倒重来」

`.badge.bad` 在 gamma 编码空间是 4.14→4.96（合规），在线性空间是 3.07（不合规）；`.badge.ok` 4.71 vs 3.41。浏览器的 alpha 合成发生在 **gamma 编码 sRGB 空间**（CSS Compositing 规范行为，与 DevTools 一致）。按线性空间复核会系统性低估约 25%，得出「四个徽标全不合格」的假结论，然后改坏一堆本来合规的地方。

`color-mix()` 的产物必须在 **OKLab 内插值**再转 sRGB，按通道近似会再偏 ±0.3。三者叠加足以跨越 0.5 的余量。

**判定优先级：DevTools 取色器实测 > OKLab 手算 > sRGB 通道近似（不采信）。**

### 6.2 light 主题：不是「套个校正式」，是需要独立设计

见 §5.2 ③。补充：`--primary` 在设计系统里承担「可点 / 选中」的全部职责（链接文字、hover、折线末点），2.30 没有辩解空间。

### 6.3 `.badge.info` 永久禁用

理由两条叠加：① 用 `--primary`，与 `--success` 同色相（162.48 vs 155），「信息」与「成功」视觉上无法区分；② dark 4.55 踩线、light 2.02 不合格。需要「主色」语义时，给 `.badge` 加 `primary` 描边，不要恢复软底规则。

### 6.4 焦点环：`:has()` 必须渐进增强，兜底必须在 `@supports` 之外

```css
/* 兜底：所有引擎都有环 —— 必须在 @supports 外 */
.card:focus-within{ outline:2px solid var(--ring); outline-offset:2px; }

@supports selector(:has(*)){
  .card:focus-within:not(:has(:focus-visible)){ outline:none; }
}
```

Tauri 的 Linux 侧是 **WebKitGTK**，老版本不支持 `:has()`。裸用 `:has()` 的后果不是「多亮一个环」，而是**整条规则被引擎丢弃、键盘焦点彻底不可见**（WCAG 2.4.7 失败）。三种引擎行为已验证：连 `selector()` 都不支持 → 整块忽略；支持 `selector()` 不支持 `:has()` → 条件为 false 整块忽略；支持 `:has()` → 键盘保留、鼠标收环。

**已知残留降级**：`.client-card:focus-within .btn{outline:none}` 在 `@supports` 外，老 WebKitGTK 上**鼠标点击仍会亮整卡绿环**。可接受（鼠标用户不需要焦点提示），但在有 `.is-current` 竖条 / `.is-selected` 描边处会被读成「选中了两样东西」。**这是平台限制，不是 bug，请勿「修复」。**

### 6.5 原型妥协清单（真机必须重判）

- **卡片结构**：外层 `div` + 卡内唯一真按钮 + `:focus-within` 整卡环。Tab 站数实测：客户端卡 **1** 站、档案卡 **1–2** 站，与 `<button>` 包裹方案基本相同，真机改造**不必**为键盘可达性牺牲「整卡可点」。**条件式警告**：若卡内增至 3 个以上按钮，必须引入 roving tabindex。
- **链路图是静态示意，当前界面未标注这一点**（全文件 `示意｜非实时` 仅命中一处 CSS 注释）。真机接真实流量时**必须**加「示意 / 非实时」标记——节点上带着 `2.4s`、`4,052 tok` 这类数字，不标注会被读成实时监控。**这是本产品的核心论点图，被误读的代价最大。**
- **时间戳全为固定假值**（`2026-11-09 …`），用于截图可复现。**回流行时间必须接在表内最新行之后**，否则会读成「丢了 N 小时」。
- **重复点击**：现版本已用「清旧 live 行 + `while(length>5) pop`」保证**永远只有 1 条 live 行**。此前版本用无条件 `pop()`，连点 5 次会吃光原始数据、表格退化为同质行——**修的是机制，没验的是场景**，这是原型最常见的退化方式。
- **`.proto-note` 已于 v0.9.0 全部下线**（14 → 0），产品文案与施工注释分离为 `.hintline` / `.design-notes` 两档。**后续不得再引入「把实现约束写进产品界面」的形式**（本次判定 P1，复发成本高）。**记一笔功劳**：两档分离由构建师主动完成并在 288 行留注释说明，比原建议的「搬进折叠区」更进一步。
- **演示专用按钮**（「模拟一次 401」「演示失败分支」）仅原型存在，上线前移除。

### 7.4 脚本自身的边界

- `46 passed` 只证明「当前数据未被截断」，不证明「更长数据不会截断」——`cc-url` 的 ellipsis 仍在。1024 下 `urlsCut: []` 是"这次没截"，不是"永不截"。真机建议对 URL 长度设上限或改两行展示。
- **状态污染已修**：H4 原报 `12,482 → 12,483`（前面用例已 +2），现 H4 开头复位 `REQ_TOTAL = 12480`，得 `12,480 → 12,481`。断言原本是关系式（`after === before + 1`），所以从未假绿；修的是 detail 里的基线可信度。
- **脚本现在自带覆盖声明**，每次跑完打印：

  > 覆盖声明：以上只覆盖「令牌 / 几何 / 状态机 / 闭环 / 数字自洽」这些可机读维度。
  > 不覆盖（必须人眼）：mock-code 块渲染、文案语气与产品边界、图标语义是否对、颜色并集与对比度、1440/1024 两档观感、投影效果、鼠标路径焦点环。
  > EXIT=0 只代表这些几何/状态断言成立，**不代表原型可发布**。

## 8. 这套原型最该保住的东西

写这一节不是夸奖。是因为下一轮改造时，**下面这几处最容易被"顺手简化"，而它们换掉产品名就立刻不成立**——是这套原型唯一无法被 AI 生成的资产。

1. **期望态 / 实际态同卡并置**。「期望 57891 · 实际 57894」写在**同一张卡的同一行**，不是两个页面各说一套。整个产品的立论就在这一行。
2. **熔断三态真的画了三个并列方块**，且写了 `连续 5 次 5xx 后退出候选` / `放一个探测请求试探上游`。不是画个状态点配个颜色。
3. **sentinel 推导出了一个产品决定**：Claude Desktop 那张卡**只给「查看指引」，不做强写**——因为强行改写会打断用户正在跑的另一个代理。这是"从机制推出克制"，不是"从设计规范推出克制"。
4. **选号器决策日志三行 = 排除熔断 → 低用量优先 → 最近失败降权**。三行就是决策全过程，没有一句解释性文字。
5. **动词选择**：「断开接管」不叫「删除」，「直连 · 不计入用量」不叫「性能模式」，「从当前配置反向快照」不叫「导入」。
6. **`cKey()` 那五个 2 字口径词**（指向/用量/差异/占用/状态）——用 5 个词解决了 8 张卡的纵向可比性，是"克制地增加结构"的范例。

**如果下一轮只能保住三样，保 1、2、3。** 其余是表达，这三样是产品。
