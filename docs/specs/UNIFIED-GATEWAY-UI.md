## 1. 落点与信息架构

**落点：网关页子导航第 7 项「统一入口」**（`GATEWAY_SUBNAV` 表加一项）。

- 两平台页自动都有：Trae 页的 `TRAE_GATEWAY_SUBNAV = GATEWAY_SUBNAV.filter((i) => i.id !== "proxy")`，不受影响。
- 子导航选中项初值从 URL 读：`?sub=unified`，非法值 fail-closed 回 `overview`（既有 `parseGatewaySubnav`，**不新增解析函数**）。
- 概览页（`overview`）建议加一行「统一入口」摘要 + 「查看」深链（`goSub("unified")`），与既有「可用模型 / 账号池」三行同构 —— 否则用户不知道有这个入口。

**为什么不是独立目的地**：本仓既有先例 —— **「Key 表与请求日志不做版本过滤：它们是跨版本的管理视图，逐行带归属即可」**。统一入口与它们同性质，放在同一目的地内最一致，且不必动 `DESTINATIONS` / 侧栏 / 路由。

**必须补的一行说明（否则像 bug）**：卡 1 顶部一行灰字 ——
> 「本入口跨全部作用域（`wb-cn` / `wb-global` / `trae-cn` / `trae-global`），上方作用域选择器对它不生效。」

★ **页头不重复**：本子视图**不渲染标题、不渲染 `max-w-[1240px]`**（页面级已有唯一页头 + scope chip）。

## 2. 页面骨架

三张卡，**顺序即数据依赖顺序**：先有网关 → 才谈有哪些命名空间 → 才谈给谁发密钥。

```
[子导航]  ┌ 卡 1 · 统一网关   ← 摘要条 / 开关 / 监听 / 端口 / 裸模型名
          ├ 卡 2 · 命名空间   ← 启用哪些（分组勾选）+ 逐段清单来源与预览
          └ 卡 3 · 统一密钥   ← 列表 + 新建（命名空间授权）
```

> ★ **2026-10-14 第二轮优化改了顺序与归属**（原型实测后）。第一版是「网关 / 密钥 / 命名空间」，
> 两个毛病：① **顺序违背依赖** —— 命名空间还没定义就先让用户授权密钥；
> ② **「启用命名空间」与「命名空间清单预览」被拆在两张卡里**，改一处要看两个地方。
> 现在合并为一张「命名空间」卡：**上面勾选、下面逐段状态，行与勾选一一对应**。

卡片几何**逐值沿用既有网关卡**（`ApiServicePage` / `TraeApiServicePage`）：
`<Card className="gap-0 py-0">` + 卡头 `.border-b px-5 py-3 text-sm font-semibold` + 正文 `px-5 py-4`。
**卡内不出现版本/区域切换控件**（「别在子组件放版本选择器」是硬约束）。

### 2.1 卡 1 顶部要有**摘要条**（与两个既有网关卡同构）

一行灰字看全：`4 个命名空间 · 3 把可用密钥 · 监听 127.0.0.1:57892` + 接入地址 + 复制按钮。
理由：第一版卡 1 直接堆 6 行配置，用户看完不知道「现在是什么状态」。两个既有网关卡都有这种「一眼看全」行。

### 2.2 「本入口跨作用域」的说明行

卡 1 顶部一行（带警示图标）：**本入口跨全部作用域；上方的作用域选择器对它不生效**。
不写这行，用户切作用域发现内容不变会当成 bug。

## 3. 卡 1 · 统一网关

### 3.1 控件（与两个既有网关卡**逐值一致**，不重新设计）

| 控件 | 交互 | 既有出处 |
|:--|:--|:--|
| 启用开关 `Switch` | `onCheckedChange` 即保存；保存中 `saving` 时旁边一枚 `<Loader2>`（**操作进行中**态，不是区块加载态）；保存成功给 `toast.success`（**不许静默**） | `ApiServicePage` 网关卡 |
| 监听地址 `Select`（回环 / 局域网） | 选局域网 ⇒ **必须走危险确认 Dialog**（`ShieldAlert` + `destructive` 确认按钮），确认后才保存 | 同上 |

| 说明行 | 「为什么两个网关都要占 `/v1/chat/completions`」+ 局域网警示 | 同上 |
| 最近失败原因 | `status.lastError` 非空才渲染（**无数据不渲染**） | 同上 |
| **裸模型名** | 一行**只读**文字（「不带前缀的模型名会被拒绝，并给出可用前缀清单」）+ 一个「看错误响应」按钮 | 本方案新增 |
| **错误响应** | 点「看错误响应」开 **Drawer**（不是内联展开） | 见 3.3 |

★ 卡 1 **不含**命名空间勾选（已移到卡 2）—— 它只讲「网关本身」。

### 3.2 文案长度纪律（第二轮踩过的）

`.srow` 的说明文字一旦超过一行，会把整行撑高、把右侧控件挤到视觉中线以下。
⇒ **每条 `.lab span` 控制在 30 字以内**，「为什么」类解释一律进 `proto-note` 或 Drawer。

### 3.3 五条错误响应用 **Drawer**，不要内联展开

第一版把展开的错误示例插在「启用的命名空间」之后 —— 离触发点隔了三行，而且把主区撑长一倍。
⇒ 参考资料型内容一律进 Drawer（`openDrawer(uniErrorsHtml(), "统一入口的错误响应（5 条）")`）。

## 4. 卡 2 · 命名空间

**一张卡讲完命名空间**：上半「启用哪些」，下半「每一段现在什么状态」。

### 4.1 启用区（**表驱动 + 按平台分组 + 网格对齐**）

```
WorkBuddy   [✓] wb-cn            [✓] wb-global
Trae        [✓] trae-cn          [✓] trae-global
            ── 显示更多程序线 ──────────────────────────────
            [ ] traework-cn      [ ] traework-global
            [ ] traecode-cn ③    [ ] traecode-global
```

- ★ **按 `product` 分组渲染**，组名取平台展示名（`PlatformDescriptor.labelKey`）。
  理由：两个平台已经 8 条；**再加一个平台（如 `qoderwork`）就是 12 条** —— 平铺成一坨必然读不动。
- 渲染**直接遍历命名空间表**并按 `product` 分组 ⇒ **新增命名空间 / 新增平台都零 UI 改动**，只加词条。
- ★ **用 CSS Grid（`repeat(auto-fill, minmax(178px, 1fr))`），不用 `flex-wrap`**：
  多行时列对齐，不再参差。第一版用 flex-wrap，8 条挤成两行且长短不齐。
- ★ **不加外层分组边框**：卡片自身已有边框，再套一层就是三层嵌套边框（第一版的毛病）。
- 默认项（派生层，= `SCOPES`）**恒显示**；扩展层（平台内部额外程序线）折叠在「显示更多程序线」之后
  （`Button variant="ghost" size="sm"` 切换，**不用** `details/summary` —— 本仓 AGENTS.md 禁止）。
- 组内为空**不渲染该组**（无数据不渲染）。
- ★ **「至少保留 1 条」的守卫走 toast，不要给 checkbox 加 `disabled`**：
  `disabled` 会让用户点不动、也看不到任何解释 —— 它和守卫逻辑互相抵消（第一版就是这个 bug）。
  正确做法：**保留可点**，点在最后一条上时给 `toast.error("至少保留一个命名空间")`，然后 `renderContent()` 把勾选态还原。
- ★ **取消勾选「仍被某些密钥授权」的命名空间** ⇒ 不弹 Dialog，但：
  1. 该复选框旁出现一枚 `warn` 徽标（数字 = 受影响的密钥数）；
  2. `toast.warning` 点名受影响的数量；
  3. **卡 3** 里对应密钥行的「授权命名空间」徽标同步变红（**跨卡联动，见 §7**）。
- 客户端名 / 程序位不放正文（`trae-cn` 已说明来源），只进 `title` —— 正文再写一遍是冗余。

### 4.2 逐段状态表（只列**已启用**的，与勾选一一对应）

| 列 | 内容 | 说明 |
|:--|:--|:--|
| 命名空间 | `code` 等宽 + **复制图标钮**（照 `model-table` 的复制 id：可反复点、1.6s 复位） | 用户要往客户端粘 |
| 客户端 · 程序位 | 客户端名（后端 `label`）+ 程序位小字 | **禁由 variant 反推** |
| 上游 function | 等宽小字：`chat_v3` / `solo_work_lite` / `—` | 排查「列得出来调不动」的第一手线索 |
| **来源 · 已识别** | 徽标（复用 `CatalogSourceBar` 的词汇：实时 / 已保存 / 内置）+ 时间 + 条数 | ★ 第一版把「来源」与「已识别」拆两列 —— **合并**：两者是同一件事的两面，拆开会让表变 7 列 |
| 原因 | 非实时必有原因；**限宽 `max-width:230px` + 两行截断，全文进 `title`** | 不截断的话一句长原因会把整张表撑宽一倍 |
| 操作 | 「看清单」展开该段前 N 条 `前缀:模型id` | **不用** `details/summary`，用受控展开 |

- 表上方：`已启用 4 / 8` 计数 + 「重新识别全部」（`<Loader2>` **操作进行中**态 + `disabled` + spinner）。
- ★ **空态**用全应用唯一的 `EmptyState`，文案直接指路上方勾选区（不再放一个孤立的按钮）。
- ★ 缺段的诚实处理：读不到客户端清单时该行 `来源 = 内置` + 原因「客户端未拉取过模型清单（需至少启动过一次）」，
  **不假装完整**。
- ★ 表下说明：**每段单独标来源与原因**；「已识别」≠「可用」，故不写「可用」。

## 6. 状态矩阵（每个状态都要有设计）

| 状态 | 表现 |
|:--|:--|
| 首次加载（`loading && !status`） | 页头常驻 + 主区 `<Skeleton>`（`h-[34px] w-[186px]` / `h-32` / `h-64`），**判据不是裸 `loading`** —— 手动刷新时保留旧内容，不把用户正看着的配置换成骨架 |
| 统一网关未启用 | 卡 1 开关关 + 状态点灰；**卡 2 / 卡 3 仍可配置**（预配），卡 1 摘要条加一句「配置会保存，启用后生效」 |
| 无统一密钥 | 卡 3 `EmptyState`（`KeyRound` 图标）+ 「创建密钥」出口 |
| 命名空间清单缺失 | 卡 2 该行 `source = 内置` + 非空原因（见 §4.2） |
| 保存失败 | `toast.error` + **不改内存态**（先落库再更新 ⇒ 行不会「假装切了」） |
| 网关运行中被改监听/端口 | 保存后按既有行为重读状态；`lastError` 非空才渲染 |
| Demo 模式 | **所有操作控件包 `DemoAction`** ⇒ 遮罩 + 统一提示（文案与 `api` 抛出的错误**逐字一致**） |

### 危险动作分档

| 动作 | 档位 |
|:--|:--|
| 吊销 / 恢复密钥 | 单次确认 Dialog（轻） |
| **删除密钥** | `destructive` Dialog（**不可逆**，明说不可恢复） |

## 7. 跨卡联动（一个细节，但决定「体系感」）

**卡 2 取消勾选某命名空间** ⇒ **卡 3 里仍授权它的密钥行**的「授权命名空间」徽标**当场变红** + `Tooltip` 说明「本入口已停用该命名空间，调用会返回 400」；卡 2 该复选框旁同时出现一枚 `warn` 徽标（数字 = 受影响密钥数）。反之不联动（加授权不影响已有密钥）。

理由：用户改的是**一处配置**，影响的却是**另一张卡里的数据** —— 不联动就会出现「密钥上明明勾着、调用却 400」的诡异体验。

## 8. 验收钩子与场景（CDP 量 DOM，**不靠肉眼读截图**）

原型里每个关键控件都带稳定的 `data-act` / `data-*` 钩子（沿用既有 `gw-*` 命名法）：

| 钩子 | 位置 |
|:--|:--|
| `data-act="uni-toggle"` / `data-uni-port` / `data-act="uni-bind"` / `data-act="uni-err"` | 卡 1 |
| `data-uni-ns="trae-cn"`（勾选）/ `data-act="uni-more"` / `data-act^="uni-expand"` / `data-act="uni-scan"` | 卡 2 |
| `data-act="uni-key-new"` / `data-uni-form` / `data-uni-biz` / `data-act="uni-key-create"` / `uni-key-revoke\|restore\|delete` / `uni-plaintext-ok` | 卡 3 |

**验收场景（每条都要能判真假）—— 已在 2026-10-14 于 headless Chrome 逐条跑通**：

1. 子导航有「统一入口」；三张卡都在；**卡头顺序 = 统一网关 / 命名空间 / 统一密钥**（顺序本身是被测对象）。
2. 默认勾选 **4** 条；点「显示更多程序线」后复选框 **8** 条；**勾选项都没有 `disabled`**。
3. 取消勾选 `trae-global` ⇒ 出现 toast；**卡 3 里文字为 `trae-global` 的红色徽标数 ≥ 1**（跨卡联动）。
4. **取消最后一条** ⇒ 勾选数**仍为 1**，且 toast 文案 = 「至少保留一个命名空间」（**阳性对照：前一轮"仅剩 1 条"必须先达到 1**，否则这条是假绿）。
5. 点「看错误响应」⇒ **Drawer 打开**且里面有 **5** 条 `.uni-err`。
6. 点「看清单」⇒ 展开出该段的 `前缀:模型id` 芯片（数量 = 该段 `models.length`）。
7. 创建流程：抽屉内复选框 **8** 个、业务转发单选项 = 已授权的 `wb-*` 数；**勾选后重渲染仍保留勾选**；提交后明文形如 `sk-uni-[0-9a-f]{16}`。
8. ★ 点遮罩后明文抽屉**仍开着**（锁定生效）；点「我已保存，关闭」才关。
9. 已吊销行：「恢复」与「删除」按钮**同时存在**（数量断言，不是文案断言）。
10. 「重新识别全部」：按钮 `disabled` **且**内含 `.spinner`（操作进行中态）。

**跑这些用例时踩到的坑（写下来免得下次白费）**：
- ★ **`renderContent()` 会重建 DOM** ⇒ 每做完一次变更**必须重新查询**元素。对已脱离文档的旧节点 `dispatchEvent` **不会冒泡到 `document`**，委托监听器根本不触发，
  于是「连点 3 次取消勾选」实际只生效了 1 次 —— 上一版探针因此把守卫误判成通过（假绿）。
- 断言要写**阳性对照**（如第 4 条必须先确认「仅剩 1 条」真的到了 1），否则「仍为 1」在 size=2 时也恒真。
- 探针代码是 JS 模板字符串 ⇒ **注释里不能出现反引号**（会把模板截断成语法错误）。

## 9. 扩展面（你特别关心的「方便后续拓展」）

> 架构侧契约见 `UNIFIED-GATEWAY-ARCH.md` §11。这里只讲 **UI 的改动面**。

### 9.1 加一个命名空间（同一平台内的新程序线）

| 落点 | 是否要改 |
|:--|:--|
| core 扩展层加一行 | ✅ 必须 |
| 前端镜像 `gateway-namespaces.ts` 扩展层同步 | ✅ 必须（门禁核对） |
| 词条一条 | ✅ 必须 |
| **UI 组件** | ❌ **零改动** —— 卡 1 自动多一个 checkbox、卡 3 自动多一行、新建 Key 的多选自动出现 |

### 9.2 加一个**新平台**（如 `qoderwork`）

| 落点 | 是否要改 | 说明 |
|:--|:--|:--|
| `product.rs`（`Product` + `Scope` + `ProductSpec`） | ✅ | 派生层，加完命名空间自动出现 |
| `registry.ts`（`Product` / `PlatformSlug` / 三张映射表） | ✅ | 仓库注释已声明此契约：「页面组件零改动」 |
| `scope.ts` 的 `SCOPES` | ✅ | `Scope` 是模板字面量类型，自动覆盖 |
| **卡 1 / 卡 2 / 卡 3** | ❌ **零改动** | 三张卡全表驱动 + 按 `product` 分组 |
| 该平台自己的账号页 / 设置页 | ⚠️ 可选（B 档） | **不阻塞**它先通过统一入口跑通 |

★ 唯一需要在 UI 里**主动补**的是**词条**（平台展示名 + 组名），因为文案不可能自动生成。

### 9.3 其余

| 要加的东西 | 改动面 |
|:--|:--|
| **一条新端点能力**（Trae 的 `/v1/responses` 就是这么补的，2026-10-22） | 卡 3 加一列（「支持 Responses」标记），不动其它 |
| **命名空间排序/分组** | 表里加 `order` 字段即可；分组已按 `product` 自动 |
| **命名空间描述文案** | 词条一条（卡 1 的每项副文案 + 卡 3 的说明） |

### 9.4 加平台时必须一起补的护栏（否则会静默半成品）

- core：`Scope::all()` 的每个 scope 都能解析到命名空间（加 scope 忘了命名空间 ⇒ 红）。
- core：命名空间集合里**任意两条 id 不得互为前缀**（`trae` / `traework` ⇒ 红）。
- 前端：`gateway-namespaces.ts` 与 core 镜像一致（`check:scope` 一并校验）。
- UI：卡 1 的分组渲染**遍历表**，不得写死「WorkBuddy / Trae」两个组名 —— 否则加平台时 UI 静默少一组。

## 10. 明确不做（避免越界）

- **不新增侧栏目的地**、**不动 `SCOPES`**、**不动账号页 / 用量页**。
- **不新增子导航图标**（原型子导航无图标，与设置子导航同口径）。
- **不搬账号页那 8 控件工具栏** —— 那是账号页的，与网关页无关。
- **不在卡内放版本/区域切换器**，也不放第二个「看起来能切」的控件。
- **不用 `details/summary`**（AGENTS.md 明确禁止用原生交互捷径替代 shadcn 组件）。
- **不做「自动给裸模型名补前缀」**这种便利功能（会在命名空间表变化时静默走错池）。
- **不把内置/兜底清单伪装成实时**（非实时必有原因的契约）。
