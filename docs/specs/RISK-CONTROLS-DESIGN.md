# 三平台合规风控设置设计

## 意图

WorkBuddy、Trae、Qoder 的账号及请求链路各自独立，当前风控参数只有部分落在 WorkBuddy 配置中，且默认值不易由使用者调整。为减少过密请求、重复提交和故障后不恰当的自动重试，三平台应有一致、可见、可调的网关风控设置。

这套设置用于控制本软件发出的请求行为，不承诺规避封禁，也不推断封禁原因。

## 目标

- 三平台共享同一份可见、可回滚的请求参数设置；账号暂停/冷却状态仍按平台、区域和账号分别保存，彼此不串用。
- 设置界面可以调整请求速率、账号/全局并发、选号最小间隔、单请求最大尝试数及流中断故障处理。
- 各平台后端归一化并校验配置；缺失字段保留旧版兼容默认值，越界值拒绝保存或钳制到明确上限。
- 覆盖三平台所有自动化的账号认证请求，包括网关转发、token 刷新、积分/签到/活动、目录与限流探测；静态资源和无账号身份的更新请求不纳入。
- 对明确的认证拒绝、封禁、限流和额度不足响应停止该账号当前自动化，不因换账号继续请求。
- 只有可判定为安全重试的幂等请求或明确的临时故障，才执行有界重试；结果不确定的 POST 不自动重放。
- 设置页展示当前生效值和验证错误，让用户知道限流单位及适用范围。

## 非目标

- 不生成或轮换设备指纹，不覆盖官方客户端设备身份。
- 不通过账号级代理、出口轮换或账号轮换隐藏账号关联、绕过平台限制或恢复已封账号。
- 不修改平台认证协议、签名字段和客户端身份头。
- 不保证上游不会封号；最终封禁原因由平台决定。

## 方案比较

### A. 三平台共用一份受限参数，风险状态分平台保存（已确认）

在「设置 → 通用」中提供一组共享设置控件和字段语义，三平台网关各自在自己的进程内执行同一份参数。账号风险状态仍由各平台分别落盘。只在明确可重试的故障上应用尝试次数；认证拒绝、封禁、限流和额度不足始终停止，不因设置更高尝试数而换号。

优点：只需维护一份参数，行为一致；平台风险状态仍独立，排查和恢复边界清楚。代价：参数变化会同时影响三个平台，调整时需一起验收。

### B. 每个平台、每个区域分别配置

三平台及两区域各自保存一份请求参数。

优点：每个作用域都能独立调整和回滚。代价：六份参数容易漂移，用户要逐份核对；当前产品没有这种精调需求。

### C. 仅修默认值，不提供设置界面

代码内统一保守默认值，使用者无法在产品设置中管理。

优点：实现范围小。代价：不满足“允许设置里自己定义”的要求，参数仍需手工改配置文件。

## 推荐设计细节

### 设置字段

三平台共用一组设置，具体字段复用现有配置字段并补齐一致语义：

| 设置 | 语义 | 安全约束 |
|---|---|---|
| 每 Key 速率上限 | 每分钟允许的入站请求数 | `0` 表示禁用此项或沿用既有语义；非零值有产品上限 |
| 每账号最大并发 | 同一上游账号同时处理的请求数 | 不允许用 `0` 表示无限并发 |
| 全局最大并发 | 单平台所有账号合计并发数 | 不允许用 `0` 表示无限并发 |
| 最小选号间隔 | 同一账号再次被选中前的间隔 | 设置在共享配置内，运行中热应用 |
| 单请求安全重试次数 | `0` 表示只发起首个请求；非零值是额外重试数，且仅作用于明确安全的暂时性故障 | 当前 Qoder 模型目录查询按该预算切换候选主机；401/403、封禁、429/模型限流、额度不足及其它非暂时性 4xx 立即停止 |
| 流中断自动失败处理 | 是否把中断暴露为客户端可识别的失败 | 不将中断转成静默换号续跑；失败后客户端可按自身策略决定是否重试 |

所有输入使用有限范围、单位标签和设置说明；页面展示当前值，保存后读取后端归一化结果回显。对旧配置缺失值采用兼容默认值，避免升级后突然放大并发或速率。

### 故障处置

- 上游明确返回认证拒绝：停止该账号自动化并标记需要重新登录/人工复核；不换号、不后台自动重试。
- 上游明确返回封禁：持久化暂停该账号的自动化请求，直到用户在官方渠道处理并手动恢复；不自动清除状态。
- 上游返回限流：按上游提供的重置时刻持久化冷却；缺少重置时刻时采用配置中的保守冷却时长。冷却期间不换号接力。
- 额度不足：停止该账号当前请求并记录状态；不使用其它账号接力消耗。
- 连接失败、超时等结果不确定的 POST：不自动重放，避免上游已处理但客户端未收到响应造成重复操作。
- 幂等 GET 或可证明上游未接收请求的连接前故障：按用户设置的尝试预算进行有限重试；每次动作记录在请求日志中。
- 用户手动重试是独立的新操作，设置页与错误信息明确提示平台限制仍适用。

### 涉及范围

- WorkBuddy：WB relay、刷新/积分/签到/旅行调用、风险状态接入和 Tauri/HTTP 设置命令。
- Trae：Trae relay/选号器、JWT 刷新/积分/模型目录调用与风险状态接入。
- Qoder：Qoder relay/选号器、token 刷新/额度/活动调用与风险状态接入。
- 三平台共享设置控件、字段展示和输入校验，不合并三套上游账号池或平台风险状态文件。
- 停用当前 WorkBuddy 账号级代理/派生身份隔离实现；旧代理配置文件保留但不再读取，避免静默删除用户数据。
- 切换账号不再写入 UID 派生设备身份；不自动覆盖现有身份文件。若此前已改写，只有在找到明确备份时才提供可审阅的恢复动作，不擅自替用户改本机文件。
- 保留认证文件单账号快照与本地账号凭据分区，因为它们用于本地数据最小化，不改变上游设备身份。
- 文档索引与现有账号风险文档同步，移除将“规避关联”描述成风控保证的内容。

## 验收标准

1. 「设置 → 通用」能读取、编辑、保存并重载三平台共用参数；账号暂停/冷却状态仍按平台、区域和账号隔离。
2. 后端拒绝非法/越界设置；保存后运行中的网关使用同一份已归一配置。
3. 三平台所有账号认证的自动化入口遇到认证拒绝、封禁、限流、额度不足时均停止相应自动化，不自动切换账号或继续请求；封禁/冷却状态跨重启保持。
4. 对不确定结果的非幂等 POST 不自动重放。
5. 旧配置文件可继续读取，未配置字段落到受限兼容默认值。
6. 设备身份保持官方客户端原值，不生成 UID 派生身份；不提供账号代理映射或代理逃生开关。旧代理配置文件不会再影响请求。
7. 三平台 Rust 单测、API 契约检查、前端类型检查和单测通过。

## 已确认方向

采用方案 A，并按以上安全边界实施。默认数值和各项上限由实现阶段依据现有配置、调用形态和可观察的上游限流响应确定，并在设置 UI 中显示；不得把任一默认值宣称为平台的安全阈值。
