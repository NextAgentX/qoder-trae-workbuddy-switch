# P9 悬浮窗 · 键盘可达性手测清单（独立窗口，**不能复用主窗口**）

> **为什么单列**：`P9-ARCH §1.7` / `P5-P12-TASKS` 附 B **A8** —— companion 是**独立 webview**
> （`?window=companion`），`decorations(false)` 没有系统标题栏，**主窗口的焦点管理一条都不适用**。
> **复用主窗口的键盘测试 = 空转**（A8 原话：「否则『通过』是空转」）。
>
> **本清单的地位**：`P9-ARCH §5 T05` 规定的验证路径之一（「**针对 companion webview 的 E2E**
> 或一份**独立手测清单**」）。代码侧的静态门禁是 `scripts/check-scope-registry.cjs` 第 **227** 条 ——
> **静态断言 ≠ 运行时行为**，故仍需按本清单在**真实独立窗口**里走一遍。

## 前置

- 桌面端（Tauri）应用运行中；悬浮窗可见性为「开」。
- 数据侧至少满足其一：**有 ≥1 条会话行** / **空态** / **读取失败态**（三种都要各走一遍第 1、2 步）。
- 打开 DevTools 指向 **companion 窗口**（不是主窗口）——第 4 步要查 DOM。

## 走查项（每条：动作 → 期望 → **可证伪**）

| # | 动作 | 期望 | 怎么判定「假通过」 |
|:--|:---|:---|:---|
| 1 | 用**键盘**从侧栏左下角图标 / 托盘菜单打开悬浮窗 | 焦点落在**第一个可聚焦行**（有可见焦点环）；**空态**时落在「刷新」按钮；骨架期不抢焦点 | 打开后按 Tab 需要按**两次以上**才到第一行 ⇒ 焦点入口缺失 |
| 2 | 连续按 **Tab** | 依次经过：各行 → 关闭按钮 →（回绕）；顺序与视觉顺序一致 | 有行**不可达**（被 `tabindex=-1` / 非 button 挡住） |
| 3 | **Shift+Tab** 反向 | 与 Tab 顺序对称 | 反向顺序错乱 |
| 4 | 聚焦某行（键盘） | 标题由占位符 `••••••••` 展开为**完整标题**，并弹出信息卡 | 展开但**明文在未聚焦时也在 DOM 里** ⇒ 隐私防线被破（DevTools 搜标题，未聚焦时应**搜不到**） |
| 5 | 在行上按 **Enter / Space** | 触发 `companion_jump`；成功 / 失败都给**明确反馈**（`role=status` / `role=alert`），**不静默** | 按键无任何反馈 ⇒ 键盘不可操作 |
| 6 | 按 **Esc** | 窗口**隐藏**（不销毁）；从侧栏 / 托盘**重开**后焦点**回到第一行** | Esc 无效果，或重开后焦点丢失（Tab 要重来一遍） |
| 7 | 拖动标题区移动窗口 | 窗口移动；**焦点不被抢**（不出现新的焦点环，焦点停在原处） | 拖动后焦点跳到某行 / body |
| 8 | Tab 到**关闭按钮** | 有焦点环；按 **Enter** ⇒ 窗口隐藏 | 关闭按钮不可聚焦 / 无标签 |
| 9 | 系统开启「**减弱动态效果**」（Windows：设置 → 辅助功能 → 视觉效果） | `running` 态状态点**不再脉冲**（静置实心点），四态仍可区分 | 仍持续脉冲 ⇒ `motion-reduce` 未生效 |
| 10 | 不悬停 / 不聚焦时**截图** | 完整标题**不出现在截图里**（只有占位符） | 截图能看到明文 |

## 记录

- 结果写入本文件下方（或 issue），逐条标注 `通过 / 失败 / 阻塞`，失败项附**复现步骤 + 窗口截图**。
- **失败即回退**：任一「焦点入口 / Esc / 行可聚焦 / 拖动不抢焦点」不通过 ⇒ P9 键盘可达性**不算完成**。
